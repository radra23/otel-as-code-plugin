# /otel-uninstrument [--service <id>] [--all] [--dry-run] [--force]

Reverse `/otel-instrument`: remove the SDK bootstrap files it generated for a service. This is the
rollback path for #50 — it undoes instrumentation artifacts **only**, never Collector configs
(`/otel-collector`) or backend Terraform (`/otel-backend`), which have their own lifecycles and
their own commands.

## The safety invariant — marker-gated deletion

A file is deleted **only if it carries the `generated by otel-as-code` ownership marker** (matched
case-insensitively). This is the same invariant the `write-guard` hook enforces for overwrites,
applied here to deletion: a file that matches a generated *name* but has no marker is something a
human wrote (or heavily edited), so it is **left in place and reported as skipped** — never
removed. The plugin deletes only what the plugin unambiguously created.

Deletion is `rm`, not a `Write`/`Edit`, so the write-guard never sees it and there is no
`.otel-force` sentinel involved. The confirmation prompt (below) is the safety gate; `--force`
only skips that prompt.

## Flags
- `--service <id>` — the service to uninstrument, by `id` from the context JSON. If omitted:
  exactly one instrumented service → use it; more than one → list them and ask (never default to
  the first).
- `--all` — uninstrument every service: sweep the whole repo for marker-carrying generated
  bootstraps rather than scoping to one service. Mutually exclusive with `--service`.
- `--dry-run` — print the removal plan and the by-hand instructions, delete nothing, and exit
  non-zero if anything **would** be removed (so it composes in CI, matching the other commands).
- `--force` — skip the confirmation prompt. Does not widen what is eligible: the marker gate still
  applies, so `--force` can never delete a hand-written file.

## Step 1: Load context

Check `.claude/otel-context.json`. Apply the freshness rule from `/otel-init` Step 1
(identity-input fingerprint, not `HEAD`). If stale or absent, dispatch
`otel-as-code:repo-context-scanner` **passing the existing cache as `priorContext`** and write
what it returns — a refresh is a merge, never a replace (see the cache ownership contract in
`agents/repo-context-scanner.md`). The scanner records existing OTel on disk in
`services[].existingOtel`, which is what this command needs to find what to remove.

## Step 2: Select the target and resolve its artifacts

Pick the service(s) exactly as `/otel-instrument` Step 2 does when `--all` is not set (one → use
it; several → prompt; `--service <id>` → that one). With `--all`, target every service.

Resolve the candidate files the same way as `/otel-instrument` Step 4 — do NOT guess a filename:
1. Use `service.existingOtel.bootstrapFiles` when non-empty.
2. Otherwise glob the service subtree (`<rootDir>/**`, excluding `node_modules`, `dist`, `build`,
   `.venv`) for the generated names. The name set is the single source of truth in
   `hooks/otel-paths.sh` — source it and use **`otel_bootstrap_globs`** (bootstrap stems ×
   extensions plus the bootstrap fixed names `otel-java.env` / `OpenTelemetry.cs`). Use this
   accessor specifically, NOT `otel_all_generated_globs` / `otel_is_generated_path`:
   `otel_bootstrap_globs` excludes `otelcol-*.yaml` **by construction**, which is what keeps this
   destructive command from ever reaching a Collector config. Do not re-add the collector or
   Terraform names by hand — they are out of scope for uninstrument, and the marker gate would NOT
   protect them (`/otel-collector` stamps its output with the same ownership marker).

If nothing is found, print "No generated bootstrap artifacts found for <target>. Nothing to
remove." and exit 0.

## Step 3: Apply the marker gate

For each candidate file, read it and check for the `generated by otel-as-code` marker
(case-insensitive). Partition into:
- **eligible** — carries the marker; will be deleted.
- **skipped** — matches a generated name but has NO marker; a hand-written file. Left in place.

Never delete a skipped file. If every candidate is skipped, say so plainly (the plugin did not
generate these) and exit without deleting.

## Step 4: Print the plan (and the by-hand steps)

Show what will happen before doing it:

```
/otel-uninstrument — checkout-api (api/, nodejs)

Will delete (generated by otel-as-code):
  api/src/tracing.ts        ✓ marker
Skipped (no marker — left in place, not generated by this plugin):
  api/src/otel-helpers.ts

Remove by hand (these live in files this plugin does not edit):
  • package.json  — remove the @opentelemetry/* dependencies added for instrumentation
  • start script  — remove `-r ./tracing.ts` (or the `import './tracing.ts'` / instrumentation hook)
  • deploy config (<service.deployment.configFiles>) — remove OTEL_EXPORTER_OTLP_ENDPOINT,
    OTEL_EXPORTER_OTLP_PROTOCOL, OTEL_*_EXPORTER, DEPLOYMENT_ENV if they were added for this
```

The "remove by hand" list is the inverse of what `/otel-instrument` printed, and it is
**print-only** for the same reason instrument printed rather than edited: these touch-points live
in hand-written files, and reverting them automatically risks clobbering unrelated changes. Adapt
the list to the target language:
- **Node.js / Python** — bootstrap file is deleted above; by hand: remove the OTel deps from
  `package.json` / `pyproject.toml`, and the `-r`/import hook from the entry or start script.
- **Java** — `otel-java.env` is deleted above (it carries the marker). The downloaded
  `opentelemetry-javaagent.jar` is **not** ours (no marker), so note it can be removed manually,
  and remind the user to drop the `-javaagent:` flag from the run command.
- **.NET** — `OpenTelemetry.cs` is deleted above; by hand: remove the
  `builder.Services.AddOtelObservability(builder.Configuration);` line from `Program.cs`, and run
  `dotnet remove package` for the four OTel packages (`OpenTelemetry.Extensions.Hosting`,
  `OpenTelemetry.Instrumentation.AspNetCore`, `OpenTelemetry.Instrumentation.Http`,
  `OpenTelemetry.Exporter.OpenTelemetryProtocol`).

## Step 5: Confirm and delete

If `--dry-run`: print the plan, delete nothing, and exit non-zero if the eligible list is
non-empty (there is drift a real run would remove).

Otherwise, unless `--force`, ask: `Delete the N file(s) above? [y/N]`. On anything but yes, exit
without deleting. Then `rm` each eligible file. Only eligible (marker-carrying) files are ever
passed to `rm`.

## Step 6: Update the cache

For each uninstrumented service, clear the removed files from `services[].existingOtel`
(empty `bootstrapFiles`, and update the coverage/summary fields to reflect that no generated
bootstrap remains) and write the context back, so a later `/otel-instrument` does not believe a
bootstrap still exists on disk. Do not touch any user-owned field (business attrs, confirmations)
— follow the cache ownership contract in `agents/repo-context-scanner.md`.

## Step 7: Summary

```
✓ Uninstrumented checkout-api: removed 1 file (api/src/tracing.ts).
  1 file skipped (no marker). See the "remove by hand" list above for package.json / start script.
  Collector config and Terraform were not touched (use /otel-collector / /otel-backend to manage those).
```
